# 前言

Java 后端工程师接入模型后，很快会遇到一组熟悉但更难处理的问题：身份从哪里来，数据能不能被访问，外部调用失败怎么办，模型提出的动作由谁执行，以及结果如何验证。

本书沿着一条客户服务链展开。客户提出问题，知识服务给出带证据的回答；需要进一步处理时，工单 Agent 组织信息并提出建议；涉及业务变更时，人工与既有系统保留控制权。模型能力因此进入一套可以观察、测试和追责的业务流程。

Spring AI 是主要实现路径，其他框架和协议作为独立实验出现。比较的重点是业务契约、依赖和回归成本，而非 API 数量。配套工程提供可运行样本，但真实项目仍需接入自己的身份、数据、容量与发布体系。
